# Room protocol v3

`/room` is a JSON WebSocket. The browser uses `wss://<host>:8787/room` during local development and same-origin `/room` behind a production HTTPS reverse proxy. Server replies carry `version: 3` on the creation, join and snapshot messages. Message types are validated with Zod in `packages/protocol`.

The host creates a four-letter code and receives a random 192-bit rejoin token. Up to five phones join with names and receive their own IDs and tokens. Session storage holds the token until the tab is closed or the room is left. A new socket with the same token replaces an old socket. A host can reconnect while the room remains in memory. Rooms expire after 30 minutes without activity.

The host chooses a clip, round count and singing order, then broadcasts `round:begin`. In `together` mode all ready singers can record; in `turns` mode the relay admits a take only from the current singer and advances after the host scores it. Phones play the reference clip and send live levels, capped at roughly 15 Hz. A phone sends one base64-encoded mono 22.05 kHz PCM16 take of at most eight seconds per round. The relay forwards it to the host, which scores the take with `packages/dsp` and broadcasts the total plus rhythm, melody, energy and vibe judge scores. The last round's judge scores are included in snapshots so phones can rejoin during a reveal. The host reveals results and advances the round. The relay rejects player attempts to send host commands and rejects duplicate take submissions and scores.

The relay limits WebSocket payloads to 600 KiB and retains no PCM after forwarding. Room and score state is in memory only; a server restart ends all rooms. The client currently sends PCM rather than compact feature tracks, and Local and Room use separate UI flows. Live room play has no voice bleed detection yet.
